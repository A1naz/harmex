# Email Campaign System - Система авторассылки писем

## Обзор

Система автоматической рассылки писем для новых пользователей. После регистрации пользователь автоматически получает серию из 21 письма в течение 21 дня (по одному письму в день).

## Особенности

- ✅ Автоматическая отправка 21 письма за 21 дней
- ✅ Индивидуальный счетчик для каждого пользователя
- ✅ Работает для пользователей с датой регистрации после 20.11.2024
- ✅ Периодическая проверка каждые 2 часа
- ✅ Защита от дублирования писем
- ✅ Логирование всех отправок
- ✅ Возможность включения/выключения для конкретного пользователя
- ✅ Шаблоны с переменными (имя, email и т.д.)

## Архитектура

### Модели

#### User (обновлена)
Добавлены новые поля:
- `emailCampaignDay` - текущий день кампании (0-21)
- `lastCampaignEmailSent` - дата последней отправки
- `emailCampaignEnabled` - включена ли рассылка (по умолчанию true)

#### EmailCampaign (новая)
Хранит шаблоны писем:
- `day` - день кампании (1-21), уникальный
- `subject` - тема письма
- `htmlContent` - HTML контент письма
- `isActive` - активен ли шаблон

#### EmailLog (новая)
Логирует все отправки:
- `userId` - ID пользователя
- `campaignDay` - день кампании
- `email` - адрес получателя
- `subject` - тема
- `status` - статус ("sent" или "failed")
- `error` - текст ошибки (если есть)
- `sentAt` - время отправки

### Сервисы

#### EmailCampaignService
Основной сервис для обработки рассылок:
- `processCampaigns()` - обрабатывает всех пользователей и отправляет письма
- `getStats()` - возвращает статистику кампании

#### MailService (обновлен)
Добавлен метод:
- `sendCampaignEmail(to, subject, htmlContent)` - отправка письма кампании

### Крон-задачи

Файл: `server/lib/cronJobs.ts`

Запускается каждые 2 часа (можно настроить):
```
0 */2 * * *  - каждые 2 часа в начале часа
```

Часовой пояс: Europe/Moscow (можно настроить)

## API Endpoints

Все endpoints требуют авторизацию и права администратора.

### Управление шаблонами

#### GET `/api/emailCampaign/templates`
Получить все шаблоны писем.

**Ответ:**
```json
{
  "status": "ok",
  "templates": [
    {
      "day": 1,
      "subject": "[HARMEX] День 1...",
      "htmlContent": "<div>...",
      "isActive": true
    }
  ]
}
```

#### GET `/api/emailCampaign/templates/[day]`
Получить шаблон для конкретного дня (1-21).

**Параметры:**
- `day` - номер дня (1-21)

#### POST `/api/emailCampaign/templates/upsert`
Создать или обновить шаблон.

**Тело запроса:**
```json
{
  "day": 1,
  "subject": "Тема письма",
  "htmlContent": "<div>HTML контент</div>",
  "isActive": true
}
```

#### DELETE `/api/emailCampaign/templates/[day]`
Удалить шаблон.

**Параметры:**
- `day` - номер дня (1-21)

### Статистика и логи

#### GET `/api/emailCampaign/stats`
Получить статистику рассылки.

**Ответ:**
```json
{
  "status": "ok",
  "stats": {
    "totalUsers": 150,
    "completedUsers": 10,
    "activeUsers": 140,
    "totalEmailsSent": 350,
    "totalEmailsFailed": 5
  }
}
```

#### GET `/api/emailCampaign/logs`
Получить логи отправок с пагинацией.

**Query параметры:**
- `page` - номер страницы (по умолчанию 1)
- `limit` - количество записей (по умолчанию 50)
- `status` - фильтр по статусу ("sent" или "failed")
- `userId` - фильтр по UUID пользователя

### Управление пользователями

#### GET `/api/emailCampaign/user/[uuid]`
Получить информацию о кампании для конкретного пользователя.

**Параметры:**
- `uuid` - UUID пользователя

**Ответ:**
```json
{
  "status": "ok",
  "user": {
    "uuid": "...",
    "email": "user@example.com",
    "emailCampaignDay": 5,
    "lastCampaignEmailSent": "2024-11-25T10:00:00Z",
    "emailCampaignEnabled": true,
    "daysSinceRegistration": 6
  },
  "emailLogs": [...]
}
```

#### POST `/api/emailCampaign/user/[uuid]/toggle`
Включить/выключить рассылку для пользователя.

**Тело запроса:**
```json
{
  "enabled": false
}
```

### Утилиты

#### POST `/api/emailCampaign/process`
Запустить обработку рассылки вручную (для тестирования).

**Ответ:**
```json
{
  "status": "ok",
  "message": "Email campaign processing completed",
  "stats": {
    "processed": 150,
    "sent": 45,
    "failed": 0,
    "skipped": 105
  }
}
```

#### POST `/api/emailCampaign/seed`
Создать тестовые шаблоны для всех 21 дней.

**Примечание:** Работает только если шаблонов еще нет.

## Переменные в шаблонах

В HTML контенте можно использовать следующие переменные:

- `{firstName}` - имя пользователя
- `{lastName}` - фамилия пользователя
- `{username}` - логин пользователя
- `{email}` - email пользователя
- `{day}` - номер дня кампании

**Пример:**
```html
<h2>Привет, {firstName}!</h2>
<p>Это день {day} вашего путешествия с HARMEX.</p>
```

## Логика работы

1. **Крон запускается каждые 2 часа**
2. **Выбираются пользователи:**
   - Зарегистрированы после 20.11.2024
   - Имеют email
   - Рассылка включена (`emailCampaignEnabled: true`)
   - Не завершили все 21 день (`emailCampaignDay < 21`)

3. **Для каждого пользователя:**
   - Рассчитывается количество дней с регистрации
   - Определяется следующий день для отправки
   - Проверяется, что не отправляли письмо за последние 23 часа
   - Проверяется, что письмо еще не было отправлено
   - Получается шаблон для этого дня
   - Заменяются переменные в шаблоне
   - Отправляется письмо
   - Логируется результат
   - Обновляется состояние пользователя

4. **Защита от дублирования:**
   - Проверка времени последней отправки (минимум 23 часа)
   - Проверка логов отправки
   - Атомарное обновление состояния пользователя

## Troubleshooting

### Письма не отправляются

1. Проверьте, что крон-задача запущена:
   - Проверьте логи сервера при старте
   - Должно быть сообщение: "Cron jobs initialized"

2. Проверьте, что есть активные шаблоны:
   ```bash
   GET /api/emailCampaign/templates
   ```

3. Проверьте пользователей:
   - Email должен быть заполнен
   - `emailCampaignEnabled` должен быть `true`
   - Дата регистрации > 20.11.2024

4. Запустите обработку вручную для диагностики:
   ```bash
   POST /api/emailCampaign/process
   ```

### Дублирование писем

Система защищена от дублирования:
- Минимум 23 часа между письмами
- Проверка логов отправки
- Если дубли все равно происходят, проверьте базу данных на консистентность

### Ошибки в логах

Проверьте настройки SMTP:
- `smtpHost`
- `smtpPort`
- `smtpUser`
- `smtpPass`

## Производительность

- Обработка 1000 пользователей занимает ~5-10 минут
- База данных индексирована для быстрого поиска
- Рекомендуется не более 1000 писем за раз

## Безопасность

- Все endpoints требуют роль "admin"
- Email адреса не отображаются в публичных API
- Логи содержат минимум персональных данных
- DKIM подпись для email
